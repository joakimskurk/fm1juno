# JUNO-106 LFO rate coefficient law

Status: Phase 0 clean-room representation of the 128-step firmware LFO-rate mapping.

The public module-ROM disassembly exposes a 128-entry 16-bit LFO coefficient sequence. Rather than reproducing the table wholesale, this note records the **piecewise arithmetic pattern** that generates the observed coefficients exactly.

## 1. Why the coefficient matters

The module LFO magnitude runs from `0x0000` to `0x1fff` and back, with hard endpoint clamps. A signed period contains four half-ramps.

For coefficient `c` and firmware-loop period `Tloop`:

```text
half_steps = ceil(8192 / c)
full_period = 4 * half_steps * Tloop
frequency = 1 / full_period
```

Because of the ceiling operation, high-rate settings are strongly quantized: several neighboring coefficient values can produce the same number of firmware passes per half-ramp.

## 2. Exact compact coefficient generator

For rate index `i` in `0..127`, the observed sequence is generated by the following piecewise integer law:

```text
if i <= 2:
    c = 5 + 10*i

else if i <= 5:
    c = 40 + 15*(i - 3)

else if i <= 7:
    c = 80 + 10*(i - 6)

else if i <= 63:
    c = 100 + 10*(i - 8)

else if i <= 95:
    c = 666 + 16*(i - 64)

else if i <= 102:
    c = 1214 + 52*(i - 96)

else if i == 103:
    c = 1580

else if i <= 105:
    c = 1650 + 70*(i - 104)

else if i <= 109:
    c = 1800 + 80*(i - 106)

else if i <= 119:
    c = 2140 + 100*(i - 110)

else if i <= 122:
    c = 3160 + 120*(i - 120)

else if i <= 126:
    c = 3550 + 150*(i - 123)

else:
    c = 4096
```

This representation is compact, deterministic and avoids embedding the original 256-byte table.

## 4. Consequence for the audible rate curve

The coefficient mapping is not a smooth exponential knob law.

At the bottom, the firmware provides fine resolution using very small coefficients. The midrange has long linear coefficient regions. The upper range accelerates through progressively larger integer step sizes.

The audible rate mapping is further quantized by:

```text
ceil(8192 / coefficient)
```

so the final frequency curve is a staircase at high settings even though the underlying coefficient continues to change.

Strict `MODEL_106` should retain both:

1. the piecewise coefficient mapping;
2. integer half-ramp step counting with endpoint clamp.

## 5. Frequency examples are calibration-dependent

Do not hard-code Hz values until `Tloop` is frozen.

For a provisional loop near 4.2–4.23 ms:

- minimum coefficient `5` gives a period on the order of tens of seconds;
- maximum coefficient `4096` gives two loop passes per half-ramp and a top rate near the published ~30 Hz region.

This naturally explains why the nominal Roland `0.1–30 Hz` specification is only an approximate front-panel range rather than a literal endpoint law.

## 6. Implementation

```text
uint16 lfo_rate_coeff(uint8 i)
{
    if (i <= 2)   return 5 + 10*i;
    if (i <= 5)   return 40 + 15*(i - 3);
    if (i <= 7)   return 80 + 10*(i - 6);
    if (i <= 63)  return 100 + 10*(i - 8);
    if (i <= 95)  return 666 + 16*(i - 64);
    if (i <= 102) return 1214 + 52*(i - 96);
    if (i == 103) return 1580;
    if (i <= 105) return 1650 + 70*(i - 104);
    if (i <= 109) return 1800 + 80*(i - 106);
    if (i <= 119) return 2140 + 100*(i - 110);
    if (i <= 122) return 3160 + 120*(i - 120);
    if (i <= 126) return 3550 + 150*(i - 123);
    return 4096;
}
```

Use explicit integer arithmetic. There is no reason to evaluate a floating exponential in the FM-1 audio/control path.

## 7. Required tests

- all segment start/end indices above;
- exhaustive `i=0..127` comparison against the independently extracted reference sequence in a development-only test fixture;
- `half_steps = ceil(8192/c)` for all 128 values;
- endpoint clamp and direction/polarity sequence;
- rate monotonicity;
- identify all adjacent indices that collapse to the same audible half-step count;
- hardware-rate measurements at selected low/mid/high indices once a reference JUNO-106 is available.

## 8. Remaining uncertainty

Only the real-time conversion remains open:

- exact average/main-loop period;
- workload-dependent jitter/variation in that period;
- whether preserving loop jitter is audibly worthwhile on FM-1.

The index-to-coefficient mapping itself no longer needs a ROM-table dependency.
